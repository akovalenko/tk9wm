# tk9wm — оконный менеджер для X11 на Tcl/Tk 9 (whale)

Reparenting-WM целиком на скрипте: ни строчки C, Xlib дёргается через
cffi. Идейный наследник tkwm (Eric Schenk, Neil McKay, 1994–95) — но без
патчей к Tk: часть машинерии TIP 47 уже в ядре Tk 9, остальное добирается
второй X-коннекцией.

Устройство: один whale-процесс, два X-соединения. Tk рисует декорации
(override-redirect-рамки), cffi-соединение владеет SubstructureRedirect
и делает WM-хирургию (save-set, reparent, map). Файлы:

- `substrate.tcl` — механизм, без которого WM не написать: cffi-обвязка
  Xlib, X-error-handler (ставится ДО загрузки Tk — порядок критичен),
  fd-помпа (worker-тред + блокирующий poll, ping-pong), manage/unmanage
  с честным чтением размера (`XGetGeometry` при manage — клиент, никогда
  не слававший ConfigureRequest, всё равно обрамляется в свой размер;
  той же геометрией читается и **позиция** окна на момент manage),
  факты WM_NORMAL_HINTS — минимум, инкременты, база (клампит WM-ресайзы;
  перечитывается по PropertyNotify; уважать ли инкременты — решение
  policy-слоя), **позиционная заявка** (`USPosition`/`PPosition` +
  `win_gravity`; move-запрос managed-клиента с заявкой уходит в
  policy-хук, остальным — отказ с синтетикой по ICCCM), живая перечитка
  `WM_TRANSIENT_FOR` по PropertyNotify (диалог может прицелиться в
  лидера уже после map), аксессоры идентичности клиента для предикатов
  (`client-class`/`-machine`/`-command`/`-pid`/`-cmdline` — argv
  локального клиента через /proc; сверка «клиент локален?» терпима к
  /etc/hosts-канонизации имени хоста Tcl-ом), adoption существующих
  окон, фокус-ядро с починкой
  внешнего PointerRoot-сброса, close-механика (WM_DELETE_WINDOW /
  XKillClient; вежливый путь с проверкой: окно всё ещё managed через
  2 с после delete — policy-хук «клиент молчит»), root-ConfigureNotify
  как сигнал смены размера экрана (RandR → policy-хук), синтетический
  ConfigureNotify (ICCCM 4.1.5), живое
  чтение титула (`_NET_WM_NAME`/`WM_NAME` по PropertyNotify),
  чтение иконки клиента (`client-icon` — `_NET_WM_ICON` → лучший из
  вложенных размеров → nearest-neighbor-ужим → PNG, собранный чистым
  Tcl-ом поверх zlib → Tk photo; кэш пер-окно, инвалидация по
  PropertyNotify и unmanage),
  WM-инициированный ресайз (`wm-resize-client`), EWMH-минимум,
  рестарт-на-месте (`TK9WM_RESTART` ClientMessage → release клиентов →
  execv самого себя; свежий код с диска, тот же pid),
  key-grab-машинерия (`wm-bind` — последовательности аккордов со
  stumpwm-семантикой: XGrabKey только на первый аккорд, квадрупелем по
  Caps/Num; хвост — под временным XGrabKeyboard, Esc/незнакомая клавиша
  = abort; переграб по MappingNotify; `grab-keys-to` — клавиатурная
  модальность для UI поверх того же граба, роутер получает press И
  release; `modifier-held` — жив ли модификатор физически, через
  XQueryKeymap — на нём fvwm-семантика alt-tab). Зовёт policy-* хуки.
- `policy.tcl` — наши локальные решения: декорации Tk-виджетами —
  титлбар-treectrl (титул с многоточием + кнопки maximize/close:
  белые квадратики-рамки с svg-глифами, fvwm-стиль, release-inside),
  canvas-подложка с 1px-обводкой и светлыми угловыми грипами, высота
  титлбара от метрик шрифта (`TitleFont`, override `TK9WM_TITLE_FONT`,
  живая смена `set-title-font`; выравнивание титула `set-title-justify`);
  пер-клиентные style-правила на предикатах (`wm-style` — предикат =
  bool-процедура над клиентом, все совпавшие правила, поздний побеждает
  по-ключево; первый ключ — `increments respect|ignore`, дефолт respect,
  снап WM-ресайзов и maximize по сетке клиента); **`filter`** —
  декларативный предикат для всех match-мест (правила `wm-style`,
  `match` панельной кнопки): `{filter -class {* firefox} -title
  "Browser*"}` — опции AND, глобы целой строкой и всегда без учёта
  регистра, `-regexp` меняет компаратор (`(?c)` в паттерне возвращает
  чувствительность), одиночный `-class`-паттерн матчит любой из
  {instance class}, пара — позиционно как в xprop, `-command` —
  WM_COMMAND с фоллбэком на /proc-argv локального клиента,
  отсутствующее свойство = не совпало; proc-предикат остаётся
  escape hatch; размещение в три
  правила — **заявка позиции клиента** (`USPosition` — слово юзера,
  дословно; `PPosition` — слово программы, с клампом к экрану и
  игнором пресловутого (0,0); gravity NW = точка рамки, Static =
  точка клиентской зоны; заявка бьёт и центровку диалога, adoption
  её тоже уважает), центровка диалога по родителю, каскад —
  и ужим не влезающего окна до экрана (не ниже заявленного минимума);
  честные move-запросы заявителей на лету (`wm geometry +x+y`
  работает); **wink** — рамка дважды моргает красным, когда клиент
  молчит на WM_DELETE_WINDOW дольше 2 с; панель переезжает к новому
  низу экрана по RandR (debounce 200 мс),
  drag за заголовок, ресайз за рамку и все четыре угла (6px-грип,
  курсоры по зонам, якорение противоположного края), maximize с
  fvwm-семантикой (workarea-проц; ресайз/перенос не сбрасывают,
  повторный тумблер возвращает сохранённое), click-to-focus, склейка
  окна с его транзиентами в один слой (raise/lower группой,
  относительными sibling-рестаками — лидер никогда не мигает над своим
  диалогом, повторный raise уже поднятого — серверный no-op), refocus
  после закрытия (лидер диалога → история фокуса); **попап-меню на
  treectrl** (клавиатура через `grab-keys-to`, мышь свободна; навигация
  Up/Down, k/j и p/n — если букву не занял хоткей пункта, Ctrl+P/Ctrl+N
  безусловно): **winops** — меню действий окна (maximize/close/destroy/
  raise/lower/move/resize с хоткей-буквами) выпадашкой из левого
  верхнего угла, у титлбара своя кнопка-меню слева; **move/resize с
  клавиатуры** — модальный режим на том же key-роутере: стрелки (и
  hjkl) двигают рамку / меняют размер (шаг 10 px, Shift = 1 px, Ctrl =
  50 px; ресайз шагает инкрементом клиента, когда тот — настоящая
  сетка, не вырожденная 1x1), Enter/space — коммит, Esc — откат к
  геометрии на входе в режим; **winlist** — список окон в
  MRU-порядке, стартовое выделение на втором пункте, записи
  **нумерованы 1-9/A-Z и номер — хоткей** (мгновенный выбор; в цикле
  зажатый модификатор прозрачен: Alt+3 = хоткей 3, ведь отпустить Alt
  ради голой цифры нельзя — меню закроется коммитом); у каждой записи
  **иконка**, источники по старшинству: style-ключ `icon` из конфига
  (слово юзера бьёт клиентское), собственный `_NET_WM_ICON` клиента,
  иначе **псевдо-иконка** — одна-две буквы класса (титула, если класса
  нет) на цветном бейдже, цвет — стабильный хэш того же имени
  (приём telegram-списка контактов); открытый аккордом
  с ещё зажатым модификатором — это **fvwm-alt-tab**: Tab бежит по
  списку с заворотом (Shift+Tab назад), отпускание модификатора =
  переключение, быстрый Alt+Tab = тумблер на предыдущее окно
  (`set-winlist-cycle off` отключает). Дефолтные бинды — в коде:
  winops на `<Alt>space` и `<Super>t w m`, winlist на `<Alt>Tab` и
  `<Super>t w w` (статичный — последовательность кончается с
  отпущенными клавишами); **панель** — своя, нижняя полоска на
  горизонтальном treectrl, существует только при объявленных в
  конфиге кнопках (`panel-button LABEL {match … launch … icon … key
  …}`); кнопка **идемпотентна а-ля wmaker**: клик или аккорд
  фокусируют самое свежее окно, найденное `match`-предикатом, а без
  находки запускают `launch`-скрипт, и кнопка вспыхивает вердиктом
  (зелёный «нашлось» / оранжевый «запускаю»); workarea отдаёт полоску
  панели (maximize и размещение новых окон её не накрывают), каждый
  raise-group завершается подъёмом панели наверх — StaysOnTop для
  бедных, пока нет слоёв.
  Реализует policy-* хуки (контракт — в шапке substrate.tcl).
- `wm.tcl` — тонкая сборка: source обоих слоёв, затем **конфиг** —
  один Tcl-файл `~/.config/tk9wm.tcl` (XDG_CONFIG_HOME уважается), при
  его отсутствии `default-config.tcl` из проекта (аннотированный
  образец, намеренно НЕ носитель дефолтов: все дефолты в коде, двух-
  строчный юзерский конфиг стартует ровно со стокового поведения;
  битый конфиг логируется и пропускается) — и `substrate-start`;
  режим demo для самотеста.

## Запуск

Нужен собранный whale (Tcl/Tk 9 + cffi + Thread): репа whalebuild
ожидается соседкой (`../whalebuild/work/linux/whale`), переопределяется
переменными `WHALE` / `LINUX`.

- `run-xephyr.sh [дисплей] [WxH]` — живой плейграунд в Xephyr (по умолчанию
  `:7 1280x800`): `Xephyr -noreset` → `xrdb -merge ~/.Xresources` → WM →
  xterm и xclock (клиенты стартуют последними, поэтому подхватывают
  ресурсы, включая DPI).

**Синтетический ConfigureNotify (ICCCM 4.1.5) шлётся по событиям, без
таймеров:** при manage, на `MapNotify` клиента, на **каждый**
`ConfigureRequest` (в том числе неудовлетворённый — иначе клиент считает,
что его подвинули) и на каждый шаг перетаскивания рамки. Копия события
уходит и на **окно рамки** — клиент вправе ждать настоящий
ConfigureNotify там (так делает Tk; см. `send_for_frame_too` у fvwm).
- Регрессии (каждая сама поднимает Xvfb, один shell-вызов):
  `run-demo.sh` (полный цикл + скриншоты), `run-adopt-test.sh` (подбор
  окон, живших до WM), `run-focus-test.sh` (ховер-тайпинг, смерть/withdraw
  фокусного окна, внешний PointerRoot-сброс), `run-withdraw-test.sh`
  (withdraw/deiconify без смерти клиента), `run-dialog-test.sh` (диалог с
  `WM_TRANSIENT_FOR` на тесном экране: центровка по родителю, прижим к
  экрану, `WM_STATE`), `run-gtk-test.sh` (GTK3-канарейка zenity),
  `run-refocus-test.sh` (закрытие диалога возвращает фокус лидеру,
  смерть окна — самому свежему по истории), `run-stack-test.sh`
  (склейка транзиентов: клик в лидера не хоронит его диалог),
  `run-title-test.sh` (титлбар следует за переименованиями клиента),
  `run-resize-test.sh` (драги за кромки и углы всех четырёх сторон,
  включая 2px-северную полосу; drag за титул; drag, начатый на корне, —
  noop), `run-size-test.sh` (честные размеры: raw-клиент без
  ConfigureRequest, заявленный минимум против ужимающего драга,
  слишком широкое окно ужимается до экрана), `run-button-test.sh`
  (maximize→workarea→restore, close шлёт WM_DELETE_WINDOW),
  `run-restart-test.sh` (рестарт-на-месте: тот же pid, клиент подобран
  обратно), `run-config-test.sh` (резолв конфига XDG → default-config;
  дефолт снапит драг wm-grid-клиента по инкрементам, dev-пресет —
  ignore + жирный центрованный титул — отдаёт сырой размер),
  `run-key-test.sh` (winops по Alt+Space: хоткей x дважды тумблерит
  maximize, навигация Ctrl+N/n/p/k/j + Enter стреляет raise;
  fvwm-alt-tab: быстрый Alt+Tab тумблерит на предыдущее окно, второй
  Tab при зажатом Alt заворачивает выделение, Alt+2 выбирает запись
  по номеру не отпуская Alt; статичный список по `Super+t w w` с
  голым номером-хоткеем; последовательность `Super+t w m` открывает
  winops через префикс-грабы; abort по незнакомой клавише не ломает
  машинерию), `run-icon-test.sh` (иконки winlist из всех трёх
  источников разом: клиентский `_NET_WM_ICON` читается и ужимается,
  style-правило конфига перекрывает, безыконный клиент получает
  псевдо-бейдж; номерные хоткеи работают и с колонкой иконок),
  `run-panel-test.sh` (идемпотентная кнопка: на пустом столе аккорд
  запускает клиента, при живом — фокусирует его и аккордом, и кликом
  мыши, отняв фокус у отвлекающего окна; maximize останавливается
  над полоской панели), `run-transient-test.sh` (поздний
  `WM_TRANSIENT_FOR`: окно без лидера целится в него после map —
  смерть отдаёт фокус лидеру, не истории), `run-wink-test.sh`
  (молчание на WM_DELETE_WINDOW: упрямый клиент получает wink,
  закрывшийся вовремя — нет), `run-randr-test.sh` (WM во вложенном
  resizeable Xephyr; ужим экрана — панель следует за низом),
  `run-place-test.sh` (позиционная заявка: adoption сохраняет угол,
  -geometry дословно, безхинтовые каскадятся, поздний move-запрос
  честно исполняется, свой +x+y диалога бьёт центровку),
  `run-kbmove-test.sh` (клавиатурные move/resize из winops: шаги
  стрелками с Shift-точностью, Enter-коммит, Esc-откат),
  `run-filter-test.sh` (in-process-батарея предиката filter против
  живых xterm и whale-клиента: глоб целой строкой и nocase, одиночный
  и позиционный `-class`, `-regexp` с `(?c)`, отсутствие свойства =
  не совпало, фоллбэк WM_COMMAND → /proc-argv у клиента,
  декорированного xprop-ом, filter в правиле wm-style и в match
  панельной кнопки).
- Диагностика живого дисплея (read-only, любой дисплей): `probe-focus.tcl`
  — снимок фокуса; `probe-watch.tcl` — вахта смен фокуса; `probe-trace.tcl`
  — что под указателем и куда ушёл фокус, построчно на каждое изменение;
  `probe-at.tcl` — цепочка окон под пикселем (пиксели врут, дерево — нет);
  `probe-stack.tcl` — root-дети снизу вверх, каждый аннотирован
  содержимым поддерева (кто над кем, рамка → клиент);
  `probe-grab.tcl` — держит ли кто пассивный grab на окне;
  `probe-pointer.tcl` — не заморожен ли указатель чужим sync-grab-ом;
  `set-focus.tcl` / `set-pointerroot.tcl` — внешние воздействия на фокус;
  `send-restart.tcl` — попросить живой WM перезапуститься на месте
  (подхват свежих исходников: release клиентов → execv себя).
  `spike/` — исторический спайк root-redirect.

**Грабля живого Xephyr:** после интерактивного ресайза окна Xephyr экран
растёт (RandR), но **XTEST остаётся зажат в стартовом прямоугольнике** —
синтетический указатель (`xdotool`) упирается в старую границу, живая мышь
ходит везде. Значит headless-драйв такой сессии врёт: задавай финальный
размер сразу (`-screen WxH`), не ресайзи окно.

История шагов и находки — `ideas/tk9-window-manager.md` в репе thoughts.
